Architecture

From camera to contract.

camera (RTSP) -> ffmpeg segments (60 s)
  -> agent: SHA-256 and SHA3-256 per segment
  -> window of 10 min -> Merkle root (SHA-256)
  -> ML-DSA-87 signature by the device key
  -> AnchorRegistry.anchor() on QoreChain  (pqcVerify on chain)
  -> receipt JSON next to the recordings

verifier (static page or CLI): clip + receipt
  -> file hash, Merkle path, verifyAnchor on chain,
     device key, ML-DSA-87 signature
KeyHolderSignsChecked by
Owner key (ML-DSA-87, registered on chain)Owner accountNative transactions (hybrid), EVM window, register and revoke a deviceChain, and the contract via pqcKeyStatus and pqcVerify
Device key (one per camera)Agent next to the cameraWindow roots, key rotationContract via pqcVerify
  • Each window commits to the previous root of its camera. Each segment commits to the previous segment. Gaps are stored on chain.
  • The camera signs the hash of a recent block. The root was signed after that block and anchored before the anchor block.
  • Anchors are immutable. There is no contract owner and no upgrade path.

Run it yourself

Install, update, back up, remove.

  • Install on the recorder computer itself: curl -fsSL https://raw.githubusercontent.com/fnoufnou/qorewitness/v0.6.0-alpha.2/install.sh | bash -s -- --yes. Options: --local-only, --new-password, --terminal (setup with questions in the terminal), --build. See INSTALL.md.
  • Other platforms: the Linux installer is tested end to end. NAS, home server, Windows and macOS use the same docker-compose.yml (short guide).
  • Other camera brands: with --terminal you can give a full stream URL, for example rtsp://user:password@192.168.1.20:554/stream. Compatibility status per brand: cameras. Research notes: CAMERAS.md.
  • Update: set the new version in ~/qorewitness/.env (QW_VERSION), then docker compose pull && docker compose up -d. The version is pinned, and QoreWitness never updates itself.
  • Back up: copy ~/qorewitness/data, at least qorewitness.env and keys. Anyone with these files can use the test account.
  • Remove: cd ~/qorewitness && docker compose down, then delete ~/qorewitness.

Post-quantum on chain

The contract checks the signature itself.

Two QoreChain precompiles do the work. Both are active on the testnet. They are not active on mainnet yet, so QoreWitness runs on the testnet only.

  • pqcVerify at 0x…0A01 checks an ML-DSA-87 signature. Every state change in the registry needs a fresh signature.
  • pqcKeyStatus at 0x…0A02 tells the contract if the owner key is registered and if possession is proven.

The audit notes map every call of a precompile to its tests.

Chain-level protection

Every EVM transaction needs a registered ML-DSA-87 key and an EVM authorisation window. The agent opens a window that is scoped to the registry only. A stolen ECDSA key cannot anchor, register, revoke or rotate anything, even inside an open window.

Drills

We attack our own system and publish the result.

  • Q-Day Drill, dry run

    13 attacks with only the ECDSA key. 0 succeeded. See testnet findings.

  • Custody drill

    10 attacks on the footage. All 5 attacks after sealing were rejected. 4 of 5 swaps before hashing were flagged. A swap with the camera's own settings was missed. See the drill.

  • Recovery drill

    The agent stops after the transaction is mined and before the receipt is written. After a restart, the receipt is rebuilt from public data and verifies (block 10,133,808).

Known limits for the jury

  • Testnet only. The PQC precompiles are not active on mainnet yet. The public site presents this as a beta with one banner on every page.
  • The keys of the owner account sit on the recorder today. An agent-key mode is designed (notes). A spike passed on the testnet. Relayed calls emit no EVM logs, so the mode waits.
  • Built: the installer, the setup in the browser, the dashboard with evidence export, QoreWitness Verify for the evidence ZIP, and the sponsor service that pays the fees during the free beta. Planned: phone alerts, a ready-made Pi image and a Windows installer.
  • Tested end to end: the Linux installer. The Docker Compose route on NAS, Windows and macOS is documented, and we still have to test it on each platform.
