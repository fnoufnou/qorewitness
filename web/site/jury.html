What it is

Sealed video for home security cameras.

A small recorder at home cuts the camera stream into short clips and fingerprints each one with SHA-256 and SHA3-256 as it is recorded. Every minute of video becomes one clip with its own fingerprints, chained to the clip before it. Every 10 minutes it builds a Merkle root over those clips, signs it with the camera's own ML-DSA-87 key and anchors it in the AnchorRegistry contract on QoreChain. The contract checks that signature with the pqcVerify precompile before it stores anything.

The owner keeps the video at home and gets a receipt per window. Anyone can check a clip with its receipt in QoreWitness Verify, a single HTML file that runs in the browser and reads the chain directly.

Try it yourself

Four checks you can run in a few minutes.

  1. Check the sample record

    Download the sample clip and its receipt, open QoreWitness Verify, press Choose files and pick both, or drop them on the page. The result is a green Original, sealed within 1 minute, read from the chain in your own browser. Verify measures from the end of the clip to the anchor. The sample is the last clip of its 10-minute window, so it reads 1 minute. A clip from the start of a window reads up to about 11 minutes.

    QoreWitness Verify is one self-contained HTML file. Its SHA-256 is 01fb584fe02806b7335ebb44c0abc1fd0da48bc1387281707046e859a59bdae8. Rebuild it with pnpm build:verifier and compare.

  2. Break it on purpose

    Press Try it: change one byte and check again. The verifier flips one bit of the clip in memory and the result turns red.

  3. Find the anchor on chain

    Open the registry on the testnet explorer and look up the sample record in block 10,653,907 (24 Nov 2026, 08:10 CET).

  4. Run the tests

    Clone the repository and run pnpm install --ignore-scripts and pnpm test. The contract tests run against a mock of the precompiles, and the app tests use a mocked chain.

Post-quantum on chain

The contract checks the signature itself.

  • pqcVerify at 0x…0A01 checks the ML-DSA-87 signature over every window root and every device change: register, rotate and revoke.
  • pqcKeyStatus at 0x…0A02 tells the contract that the owner key is registered and that possession is proven.
  • Each window commits to the previous root of its camera, and the signed block hash bounds the time on both sides.
  • Anchors are immutable. There is no contract owner and no upgrade path.

Chain-level protection

Every EVM transaction on QoreChain needs a registered ML-DSA-87 key and an EVM authorisation window. The recorder opens a window that is scoped to the registry only. A stolen ECDSA key cannot anchor, register, revoke or rotate anything, even inside an open window.

Known limits, stated openly

  • Testnet only. The PQC precompiles are not active on the QoreChain main network yet, so the public site presents QoreWitness as a beta.
  • The keys of the owner account sit on the recorder today. An agent-key mode is designed and a spike passed on the testnet, but relayed calls emit no EVM logs, so it waits until after the submission (notes).
  • The Linux installer is tested end to end. Docker Compose on a NAS, Windows and macOS is documented and still has to be tested on each platform.
  • A seal proves that a file has not changed since it was sealed. It cannot prove that the scene was real.
